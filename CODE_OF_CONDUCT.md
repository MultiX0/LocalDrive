# Code of conduct

## The short version

Be decent to people. Assume they are acting in good faith. Argue about the
code, not the person writing it.

## What is expected

- Keep criticism about the work. "This leaks a file handle" is useful. "This is
  amateur work" is not, and says nothing the first sentence did not.
- Accept that people have different amounts of experience, time and English.
  Someone struggling to explain a bug is still reporting a real bug.
- Take a "no" without relitigating it. Maintainers turn down changes for
  reasons that are not always worth writing an essay about.
- Assume the other person is trying to help until they clearly are not.

## What is not

- Harassment, in the issue tracker or anywhere else it follows someone from
  here.
- Insults or dismissals aimed at a person, their background, or their
  identity.
- Sexual attention or imagery. This is a file server project.
- Publishing someone's private information.
- Sustained disruption: reopening settled arguments, brigading a thread,
  demanding unpaid work from maintainers.

## Scope

This applies in the repository, in issues and pull requests, and anywhere
someone is representing the project.

## Reporting

Email the maintainer through the address on the
[MultiX0](https://github.com/MultiX0) profile, or open a GitHub issue if the
matter is not sensitive.

Reports are handled privately. What happens next depends on what happened, and
ranges from a quiet word to a block. Maintainers who behave this way are held
to it the same as anyone else.

## A note on enforcement

This project is small. There is no committee and no appeals process, just
people trying to run something fairly. The absence of process is not an
invitation to test the edges of it.
