# Notes for coding agents: the website

Everything above this line is generated by `next dev` and rewritten on every
run. Leave it alone. Everything below is the project's own, and lives here
rather than in a separate file so that both arrive together in any tool that
reads `AGENTS.md`.

Local rules for `landing/`. The root [`AGENTS.md`](../AGENTS.md) covers
everything general and is not repeated here.

## What this is

A Next.js site that is both the marketing page and the rendered documentation.
It reads `../docs` and `../LICENSE` from the repository at build time.
`lib/docs/source.ts` resolves the docs directory, and `lib/docs/render.ts`
turns each file into a page.

Nothing is copied. There is one source for the documentation and it is `docs/`.
Do not add a Markdown file here to document the product.

## The build is the link checker

```
npm run build
```

It parses every file in `../docs`, resolves every internal link, and throws on
the first one that does not resolve or on a file missing a frontmatter title.
This is the only link checking the project has, so a change to `docs/` is not
finished until this passes.

If you add a documentation directory, check whether it needs a display name.
Title-casing a directory produces "Api Reference", so section labels are held
in a small map rather than derived.

## Brand

The site matches the application exactly. The palette, radii, typography and
motion come from the Flutter app and are declared once as CSS custom
properties. Do not hardcode a hex value in a component.

The two rules that are easiest to break by accident:

- **No shadows and no gradients.** Every surface is a flat fill with a 1px
  border. Reaching for a shadow means the design has gone off brand.
- **Two accent colours only.** The file type colours are semantic and must not
  be used for decoration.

Respect `prefers-reduced-motion` on every animation, without exception.

## Commands shown on this site are a second copy, and they rot

The pages here hand-write terminal blocks that also exist in `docs/`. Nothing
checks the two against each other, so the copy on this site goes stale silently
while the documentation stays right.

That is not hypothetical. Every one of these was live on the site at once, and
every one was already correct in `docs/`:

- `./localdrive` as the first command, when the released file is called
  `server` and is not executable until `chmod +x`.
- `https://localhost:7443` and `https://<your-ip>:7443`, on a server that
  serves plain HTTP unless a domain is set.
- "the server made its own certificate", which is the opposite of a documented
  decision: there is no self signed certificate anywhere, because it would make
  the app refuse to connect.
- "you lose HTTPS, drive management and network discovery" without Docker,
  when HTTPS stopped being on that list once the binary got its own certificate.
- A hand written systemd unit, when `localdrive service` writes one.

So: **before changing or adding a terminal block here, open the matching page in
`docs/` and copy what it says.** If they disagree, `docs/` wins and the site is
the bug. If you change behaviour anywhere in the repository, search this
directory for the commands it affects, because the link checker will not find
them for you.

## Content rules

- Claims on the marketing page must be true of the software as it exists. If a
  capability is planned rather than built, it does not go on the home page.
  [`VISION.md`](../VISION.md) is where direction belongs.
- Screenshots are captures of the running application, not mockups, and the
  page says so. Keep that true.
- No em dashes, no exclamation marks, no superlatives. Same voice as `docs/`.

## Before you finish

```
npm run build
npx eslint
```

The site must build with no type errors, and the body must not scroll
horizontally at 375, 768 or 1440 pixels wide.
